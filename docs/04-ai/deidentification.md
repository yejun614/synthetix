# 비식별화와 검열

> 상태: 초안 · 갱신: 2026-10-21 · 관련: [ai-gateway.md](ai-gateway.md), [data-protection.md](../03-security/data-protection.md)

## 탐지기 (Detector)

여러 탐지기를 함께 쓰고, 결과를 합칩니다. 위에 있는 탐지기일수록 정확합니다.

| 순서 | 탐지기 | 대상 | 비고 |
|---|---|---|---|
| 1 | **분류 메타데이터** | 엔티티나 DTO에서 온 구조화 데이터 | `[Classified]` 특성을 보고 결정합니다. 가장 정확하므로 기본 수단입니다 |
| 2 | **정규식 + 검증** | 자유 텍스트 (문서, 사용자 입력) | 아래 패턴 표 참고 |
| 3 | **사전** | 자유 텍스트 | DB에 있는 직원 이름, 고객사·협력사 이름, 프로젝트 코드명. Aho-Corasick 알고리즘으로 찾습니다 |
| 4 | **NER 모델** (Phase 4) | 자유 텍스트 | 사전에 없는 사람 이름이나 주소. 작은 로컬 모델을 씁니다 |

### 정규식 패턴

| 유형 | 토큰 | 검증 방법 |
|---|---|---|
| 주민등록번호, 외국인등록번호 | `RRN` | 생년월일이 실제 날짜인지 확인합니다. **2020년 10월 이후 발급분은 검증 숫자가 없으므로** 체크섬 검사에 의존하지 않습니다 |
| 휴대전화, 전화번호 | `PHONE` | 국내 번호 형식 |
| 이메일 | `EMAIL` | |
| 사업자등록번호 | `BRN` | 체크섬 |
| 법인등록번호 | `CRN` | 체크섬 |
| 카드번호 | `CARD` | Luhn 알고리즘 |
| 계좌번호 | `ACCOUNT` | 형식이 은행마다 달라서 오탐이 많습니다. 주변에 "계좌", "입금", 은행명 같은 단어가 있을 때만 탐지합니다 |
| 여권번호, 운전면허번호 | `PASSPORT`, `DRIVER_LICENSE` | |
| IP 주소 | `IP` | |
| API 키, 비밀번호 | `SECRET` | `AKIA...` 같은 클라우드 키 패턴, 엔트로피가 높은 문자열 |

### 한국어에서 주의할 점

- 한국 사람 이름은 2~3글자라서 일반 단어와 헷갈리기 쉽습니다. 그래서 이름은 **DB 사전에 있는 이름만** 탐지합니다. 사전에 없는 이름은 Phase 4의 NER로 보완합니다.
- 조사가 붙은 형태도 찾아야 합니다. 예: "홍길동님이", "홍길동 과장은"

## 가명화와 복원

```
원문:   "홍길동 과장(010-1234-5678)이 A은행 차세대 프로젝트 PM입니다."
가명화: "[PERSON_1] 과장([PHONE_1])이 [CLIENT_1] 차세대 프로젝트 PM입니다."
```

- 토큰 형식은 `[{TYPE}_{n}]`입니다. 요청 하나(채팅이면 대화 하나) 안에서 같은 값은 항상 같은 토큰이 됩니다.
- 매핑 표(`PseudonymMap`)는 요청 범위의 메모리에만 둡니다. 채팅에서는 대화 세션 동안 서버 메모리(암호화된 캐시)에 두고, 대화가 끝나면 지웁니다. **DB에는 저장하지 않습니다.**
- 복원할 때는 LLM 출력에서 토큰을 찾아 원래 값으로 바꿉니다. 매핑에 없는 토큰은 그대로 둡니다. 토큰이 깨진 형태로 나와도(예: `PERSON_1`, `[Person 1]`) 최대한 찾아서 바꿉니다.
- 정책상 `Restricted` 값은 아예 **제거**합니다. 토큰도 남기지 않고 `[REDACTED]`로 바꿉니다.
- 금액은 개인정보가 아니라 업무 기밀(`Confidential`)입니다. 외부 공급자로 보낼 때는 범주화(예: "10억~50억")하는 방법을 쓸 수 있습니다 (용도별로 설정).

## 검열 (ContentGuard)

| 위치 | 규칙 | 위반 시 처리 |
|---|---|---|
| 입력 | 가명화한 뒤에도 `Restricted` 패턴이 남아 있음 | 차단 |
| 입력 | 관리자가 정한 금칙어나 기밀 프로젝트명 | 차단 또는 가명화 |
| 출력 | 매핑에 없는 민감정보가 나타남 (모델이 지어냈거나 학습 데이터에서 나온 값) | 가림 |
| 출력 | 구조화 스키마 위반 | 다시 시도한 뒤에도 실패하면 오류 |
| 출력 | 시스템 프롬프트 노출, 지시 무시의 흔적 | 차단하고 감사 로그에 기록 |

규칙은 `ai` 스키마에 저장합니다. 관리자 화면에서 관리하고, 바꿀 때마다 감사 로그를 남깁니다.

## 품질 목표 (초안)

| 유형 | 재현율 목표 |
|---|---|
| RRN, CARD, SECRET | 100% (하나라도 놓치면 릴리스하지 않음) |
| PHONE, EMAIL, BRN | 99% 이상 |
| 사전에 있는 PERSON, CLIENT | 99% 이상 |
| ACCOUNT | 95% 이상 (오탐도 함께 관리) |

- 평가 말뭉치는 `tests/Synthetix.AI.Evals/Deidentification/`에 둡니다. 가상 데이터로 만든 계약서, 이력서, 회의록입니다.
- 탐지기 단위 테스트는 일반 테스트에 포함해서 CI에서 항상 돌립니다.
