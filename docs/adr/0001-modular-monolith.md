# ADR-0001: 모듈형 모놀리스 아키텍처

- 상태: 제안
- 날짜: 2026-10-21

## 배경

ERP는 업무 영역(프로젝트, 인사, 회계)이 뚜렷하게 나뉩니다. 하지만 영역끼리 데이터가 많이 연결됩니다(프로젝트 손익 = 계약 + 투입 + 단가 + 비용). 개발자는 1명입니다. 그리고 고객사 서버(IIS)에 설치해서 운영해야 합니다.

## 결정

배포 단위는 하나(ASP.NET Core 앱 하나)로 하고, 내부를 **모듈**로 나눕니다.

- 모듈마다 프로젝트, DB 스키마, DbContext를 따로 둡니다.
- 모듈끼리는 `.Public` 인터페이스(동기 조회)와 Outbox 기반 통합 이벤트(비동기 반응)로만 통신합니다.
- 경계는 아키텍처 테스트로 강제합니다.

## 검토한 대안

| 대안 | 장점 | 단점 |
|---|---|---|
| 마이크로서비스 | 독립 배포와 확장 | 설치형 고객사에서 운영하기가 너무 복잡함, 분산 트랜잭션, 1인 개발에 과함 |
| 계층형 단일 프로젝트 | 가장 단순함 | 시간이 지나면 모듈 경계가 무너짐. 영역끼리 강하게 묶여 버림 |
| **모듈형 모놀리스** | 배포가 단순함. 경계가 명확함. 필요해지면 모듈을 서비스로 떼어낼 수 있음 | 경계를 지키려면 규칙과 테스트가 필요함 |

## 결과

- 설치는 IIS 사이트 하나와 DB 하나로 끝납니다.
- 다른 모듈의 테이블을 JOIN할 수 없어서, 화면용 조합 쿼리가 조금 번거로워집니다.
- Outbox 디스패처와 이벤트 멱등 처리를 직접 구현해야 합니다.
- 나중에 떼어내기 좋은 후보는 AI 모듈입니다(GPU 서버와 함께 둘 수 있음).
