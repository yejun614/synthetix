# ADR-0002: 회사별 설치형 (단일 테넌트) 배포

- 상태: 제안 (미결 사항 Q1의 가정)
- 날짜: 2026-10-21

## 배경

로그인 화면에서 회사 서버의 Base URL을 입력하는 방식은, 회사마다 서버가 따로 있다는 뜻입니다. 대상 고객인 SI/SM 기업은 계약, 인사, 원가 데이터를 외부에 두는 것을 꺼립니다. 망분리 환경도 흔합니다. 게다가 AI 기능에 로컬 LLM을 쓰려면 고객사 안에 GPU 서버가 있어야 합니다.

## 결정

설치 한 번에 한 회사가 씁니다. 데이터 모델에 테넌트 ID를 넣지 않습니다. Azure에도 "회사별로 하나씩 배포"하는 단일 테넌트 방식을 유지합니다.

## 검토한 대안

| 대안 | 장점 | 단점 |
|---|---|---|
| **회사별 설치형** | 데이터 주권, 망분리 대응, 단순한 데이터 모델 | 회사별 업그레이드 운영이 필요함 (자동 업데이트와 설치 번들로 줄임) |
| 멀티테넌트 SaaS | 운영 효율, 한 번 배포로 모두 적용 | 테넌트 격리 설계와 보안 검증 부담. 로컬 LLM 요구와 맞지 않음 |

## 결과

- 모든 쿼리에 테넌트 조건을 붙일 필요가 없습니다.
- 서버와 클라이언트 버전을 회사마다 맞춰야 합니다. [ADR-0004](0004-velopack-auto-update.md)의 "서버가 자기 클라이언트를 제공"하는 방식으로 해결합니다.
- 나중에 SaaS로 바꾸려면 큰 비용이 듭니다. 지금 포트폴리오 범위에서는 받아들일 수 있는 비용입니다.
