# ADR-0007: 조직 기반 역할 부여 (상속 + 허용 합산 + 예외)

- 상태: 승인 (2026-10-21)
- 날짜: 2026-10-21
- 상세: [authorization.md](../03-security/authorization.md), [organization.md](../02-domain/organization.md)

## 배경

인사팀은 부서, 팀, 구성원 단위로 역할과 접근 범위를 설정하려고 합니다. 사람마다 일일이 권한을 주면 다음 문제가 생깁니다.

- 입사, 이동, 조직개편이 있을 때마다 권한을 손으로 고쳐야 합니다.
- 권한이 남거나 빠지는 사고가 납니다.

동시에 관리자는 "이 사람이 왜 이 권한을 갖는가"를 항상 설명할 수 있어야 합니다.

## 결정

- 역할 부여 대상은 `User`, `OrgUnit`, `OrgHead` 세 가지입니다. `OrgUnit`과 `OrgHead`는 하위 조직까지 상속할 수 있습니다.
- 유효 권한은 **허용을 합쳐서만** 계산합니다. 일반적인 Deny 규칙은 두지 않습니다. 대신 특정 부여에서 특정 구성원을 빼는 Exclusion만 허용합니다.
- 데이터 범위는 "근거 조직"을 기준으로 하는 상대 범위(`OwnUnit`, `OwnUnitAndDescendants`)와 절대 범위(`All`, `SpecifiedUnits`)를 함께 지원합니다.
- 조직의 원본은 HR 모듈에 두고, Identity는 이벤트로 프로젝션을 유지하면서 권한을 계산합니다.
- 조직개편과 역할 변경은 적용하기 전에 권한 시뮬레이션으로 영향을 확인할 수 있습니다.

## 검토한 대안

| 대안 | 장점 | 단점 |
|---|---|---|
| 개인 단위 RBAC만 | 단순함 | 조직개편이 있을 때마다 대량으로 수정해야 함. 사고 위험 |
| **조직 상속 + 허용 합산 + 예외** | 조직 변동이 자동으로 반영됨. 결과를 설명할 수 있음 | 계산 로직과 캐시 무효화가 필요함 |
| 조직 상속 + Allow/Deny 우선순위 | 표현력이 큼 | 우선순위 충돌을 이해하기 어려움. 결과를 설명하기 어려움 |
| ABAC (정책 언어, 예: OPA) | 매우 유연함 | 관리자(인사팀)가 다루기 어려움. 설치형 운영에 부담 |

## 결과

- 권한 변경이 수 초 지연될 수 있습니다(이벤트 전파). 즉시 차단이 필요한 경우에는 세션 폐기로 보완합니다.
- 조직 계층 조회에 SQL Server `hierarchyid`를 씁니다 (EF Core HierarchyId 지원).
- 권한 계산기는 순수 함수로 만들어 단위 테스트를 충분히 합니다. 상속, 겸직, 예외, 기간 만료의 조합을 모두 다룹니다.
