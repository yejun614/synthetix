# ADR-0005: AI Gateway를 통한 단일 출구와 로컬 LLM

- 상태: 제안
- 날짜: 2026-10-21
- 상세: [ai-gateway.md](../04-ai/ai-gateway.md), [deidentification.md](../04-ai/deidentification.md)

## 배경

AI를 챗봇뿐 아니라 업무 흐름 곳곳(계약서 추출, 일정 위험, 비용 설명 등)에 넣으려고 합니다. 이렇게 호출하는 곳이 많아지면, 각 기능이 따로 LLM을 부를 경우 비식별화가 빠지거나 감사 기록이 누락되기 쉽습니다. 동시에 업무 데이터가 외부로 나가면 안 됩니다.

## 결정

- 모든 LLM 호출은 `IAiGateway` 하나를 거칩니다. 탐지 → 가명화 → 정책 → 검열 → 복원 → 감사 순서를 Gateway가 강제합니다.
- 기본 모델은 사내 로컬 LLM입니다(Ollama, OpenAI 호환 API). 외부 공급자는 기본적으로 차단하고, 관리자가 명시적으로 켜야 합니다.
- `Microsoft.Extensions.AI`로 추상화해서, 모델이나 공급자를 바꿀 때 설정만 고치면 되게 합니다.
- AI는 제안만 합니다. 데이터를 바꾸는 작업은 항상 사람이 확인한 뒤에 저장합니다.

## 검토한 대안

| 대안 | 장점 | 단점 |
|---|---|---|
| **중앙 Gateway** | 정책을 한곳에서 적용, 누락 방지, 감사 일원화 | Gateway가 병목이 되거나 장애 지점이 될 수 있음 (시간 제한과 기능 단위 저하로 대응) |
| 기능마다 직접 호출 | 빠르게 구현 가능 | 비식별화와 감사가 누락될 위험 |
| 외부 LLM (Azure OpenAI 등)을 기본으로 사용 | 성능이 좋음, GPU 불필요 | 데이터 주권 요구를 어김. 망분리 환경에서 불가능 |

## 결과

- GPU 서버가 필요합니다 (미결 사항 Q4). 로컬 모델은 성능이 낮을 수 있으므로, 구조화 출력, 평가셋, 사람의 확인으로 보완합니다.
- 다른 모듈이 LLM SDK를 참조하지 못하게 아키텍처 테스트로 막습니다.
