# ADR-0006: 민감 필드는 애플리케이션 계층에서 암호화

- 상태: 제안
- 날짜: 2026-10-21
- 상세: [data-protection.md](../03-security/data-protection.md)

## 배경

주민등록번호, 계좌번호 같은 `Restricted` 필드는 법적으로 암호화해야 합니다. DB 관리자나 백업 파일을 통해 원문이 노출되는 것도 막아야 합니다.

## 결정

- `Restricted` 필드는 EF Core ValueConverter로 **애플리케이션에서 AES-256-GCM으로 암호화**한 뒤 저장합니다.
- 키는 키 저장소에 둡니다. 설치형은 Windows 인증서 저장소나 Data Protection, Azure는 Key Vault를 씁니다. 키 버전을 암호문 앞에 붙여서, 나중에 키를 교체할 수 있게 합니다.
- 정확히 일치하는 값을 검색해야 하면 HMAC 블라인드 인덱스 컬럼을 따로 둡니다.
- DB 전체에는 TDE를 추가로 적용합니다(지원하는 에디션에서).

## 검토한 대안

| 대안 | 장점 | 단점 |
|---|---|---|
| **애플리케이션 암호화** | DB 관리자도 원문을 볼 수 없음. 에디션과 무관함. 클라우드로 옮기기 쉬움 | 범위 검색과 정렬이 안 됨. 키 관리를 직접 해야 함 |
| SQL Server Always Encrypted | DB가 지원하는 기능. 결정적 암호화로 일치 검색 가능 | EF Core와 드라이버 설정이 복잡함. 키 관리 인프라가 필요함 |
| TDE만 사용 | 설정이 간단함 | DB 접속 권한이 있으면 원문이 보임 |

## 결과

- 암호화 필드로는 정렬하거나 부분 검색할 수 없습니다. 업무상 그런 요구가 없는 필드에만 적용합니다.
- 키를 잃으면 데이터를 복구할 수 없습니다. 키 백업 절차를 설치 문서에 넣어야 합니다.
