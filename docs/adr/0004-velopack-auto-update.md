# ADR-0004: Velopack 기반 데스크톱 자동 업데이트

- 상태: 제안
- 날짜: 2026-10-21
- 상세: [client-update.md](../01-architecture/client-update.md)

## 배경

회사별 설치형이라서 고객사마다 서버 버전이 다를 수 있습니다. 데스크톱 클라이언트는 자기가 접속하는 서버와 버전이 맞아야 합니다. 대상 PC는 관리자 권한이 없거나 인터넷이 막혀 있을 수 있습니다.

## 결정

- 업데이트 도구는 Velopack을 씁니다.
- 각 회사 서버가 `/updates/win/`에서 **자기 버전과 맞는 클라이언트 패키지**를 제공합니다. 서버 설치 번들에 클라이언트 패키지가 함께 들어 있습니다.
- 로그인하기 전 서버 확인 단계에서 `minVersion`과 `latestVersion`을 비교해 강제 업데이트 또는 선택 업데이트를 합니다.

## 검토한 대안

| 대안 | 장점 | 단점 |
|---|---|---|
| **Velopack** | Avalonia 지원, 차등 업데이트, 관리자 권한 없이 설치, 정적 파일로 배포 | 비교적 새로운 프로젝트 |
| ClickOnce | 오래 써 온 방식, Windows 기본 지원 | Avalonia나 최신 .NET 배포 방식과 잘 맞지 않음. 기능이 제한적 |
| MSIX / App Installer | OS 통합 | 코드 서명이 필수. 사내 정책에 따라 막힘 |
| 직접 구현 | 완전한 통제 | 무결성 검증, 차등 업데이트, 롤백을 모두 직접 구현해야 함 |
| 중앙 업데이트 서버 (예: GitHub Releases) | 운영이 단순함 | 망분리 환경에서 동작하지 않음. 고객사 서버 버전과 어긋날 수 있음 |

## 결과

- 서버를 배포하면 클라이언트 배포도 끝납니다. 버전 불일치는 구조적으로 줄어듭니다.
- IIS에 `.nupkg` MIME 타입을 등록해야 합니다.
- 코드 서명 인증서가 없으면 SmartScreen 경고가 뜹니다 (미결 사항 Q6).
